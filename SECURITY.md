# Security Policy

## Supported Versions

Only the latest active development release of Sakurava is supported for security patches.

## Reporting a Vulnerability

Because Sakurava is designed to manage private local media catalogs, we take security, local sandbox safety, and file permission boundaries very seriously.

If you discover a security vulnerability (such as a local command injection, directory traversal via file protocols, SQL injection, or unauthorized filesystem access), please **do not open a public issue on GitHub**.

Instead, please report the vulnerability privately by:
1. Using the **GitHub Private Vulnerability Reporting** feature on the repository (if enabled).
2. Contacting the repository owner/maintainers directly at [EMAIL_ADDRESS].
3. Proposing a fix or detailing the reproduction steps clearly.

We will investigate the report and work on a fix as quickly as possible. Once the issue is resolved, a patch will be published.
